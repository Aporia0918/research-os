## 只在云端测过、没在真机上测过的

- APK 没有装到任何一台真手机上。安卓系统浏览器（WebView）能不能跑 module 类型的 Web Worker、Pyodide 在中低端机上要多少内存、第一次加载要多久，都还不知道。电脑上的 Chrome 能跑，只能说明大概率可以。
- 从别的 App 系统分享进来，现在默认打开「析微」页，这段只有代码和单元测试，没在手机上点过。
- 第一次打开引擎的等待时间，手机上预计比电脑长；代码里给第一次调用留了 90 秒（团队估计），之后每次 20 秒，超时会自动重启引擎。
- 引擎给的说明文字只有中文；英文界面下这几句还是中文。

## 和计划书不一样的地方

- 每道题最多试 8 个候选改动，凑够 3 个通过四道检查的就停（计划书写的是「试 3 个」）。只试 3 个时，求最值和带参数的题经常一个都凑不出来。
- 常见错法库里去掉了「0/0 → 不存在」，按补充方案 1.2 的判定表：把单侧极限当双侧答「不存在」应该算漏看条件，不算常见错法。
- 答错但能被两处漏看同时解释时，其中一个知识点的掌握度可能小涨一点。这是补充方案里每次作答后都有学习概率 T = 0.1 造成的，没改。
- 变式债按「一道题 + 一个条件」记一笔。复测时出的变式不一定还改同一个条件，但对错都记在这笔债上；过手看的是这个条件的掌握度。

## 还没做出变式的题

OpenStax 里 os48-30、os48-40、os48-48、os23-13 四道，候选改动都没过四道检查（多是改完答案不变或算不出确定值）。页面上会提示「这道题先不出变式」，可以只记一笔进账本。

## 怎么复现

```
cd packages/xiwei
pip install --require-hashes -r requirements.txt && pip install pytest ruff
ruff check . && python -m pytest -q && python eval.py
python build_site.py ../../apps/mobile/public/engine   # 打包手机用的引擎，约 18 MB，不进仓库
cd ../../apps/mobile && npx vitest run
```
